# GEMM scaling in XSim and on the Basys 3

The dense sweep multiplies a 4×N matrix by an N×4 matrix for every integer
`N` from 1 through 32; selected runs extend to `N=111`. All three programs
use the same deterministic input generated by `scripts/fpga/benchmark_gemm.py`.
All 16 output words are compared with an independent Python result. Arithmetic
is 16-bit.

The core runs at 25 MHz. Cycle counts start when reset releases and stop at
`HALT`; bitstream programming and UART readback are outside the interval.
The dense sweep uses the FPGA memory configuration in Vivado Simulator. Selected
points are also measured on the connected Basys 3. Each board measurement is
one UART capture with all 16 output words checked against the Python reference.

![GEMM cycles and SIMD/SIMT difference for N=1 through 32](fpga-gemm-scaling.svg)

The [complete N=1–32 XSim table](fpga-gemm-sweep-n1-32.csv) contains scalar,
SIMD, and SIMT results for every N. A [selected XSim table through
N=111](fpga-gemm-sweep-selected-n8-111.csv) records larger points. The
[hardware measurements](fpga-gemm-hardware.csv) record the runs checked on the
board. Raw simulator and Vivado logs are under `build/fpga/` in the local
workspace.

| N | SIMD cycles on board | SIMT cycles on board | Faster program |
| ---: | ---: | ---: | --- |
| 15 | 5,054 | 4,983 | SIMT by 71 cycles |
| 16 | 3,166 | 4,983 | SIMD by 1,817 cycles |
| 31 | 6,206 | 6,135 | SIMT by 71 cycles |
| 32 | 4,318 | 6,135 | SIMD by 1,817 cycles |
| 111 | 11,966 | 11,895 | SIMT by 71 cycles |

At `N=16`, scalar takes 7,038 cycles, SIMD 3,166 (2.22× faster), and SIMT
4,983 (1.41× faster) on the board. At `N=111`, scalar takes 37,438 cycles;
SIMD and SIMT are 3.13× and 3.15× faster, respectively. All three N=111
hardware counts match XSim.

SIMT is 71 cycles faster than SIMD at `N=7, 15, 23, 31`. These are the cases
with seven elements after the last complete eight-element SIMD chunk: SIMD
executes those seven elements through its scalar tail, while SIMT executes one
masked eight-lane block. At `N=8, 16, 24, 32`, SIMD processes a full vector
chunk instead and is 1,817 cycles faster than SIMT. This is a repeating
boundary effect, not a steady SIMT advantage as N grows.

The selected XSim table shows the same tail effect near the 1,024-word RAM
limit: from `N=104` to `N=111`, SIMD rises from 9,502 to 11,966 cycles (+26%)
while SIMT rises from 11,319 to 11,895 (+5%). The N=111 board run confirms
SIMT's 71-cycle lead there.

Within each eight-element interval, each extra scalar-tail element adds 352
cycles to SIMD across the 16 outputs; SIMT's cycle count stays flat because it
already paid for the padded block. At the next multiple of eight, SIMD replaces
the seven-element tail with a vector chunk and its count drops by 1,888 cycles.

To regenerate the dense sweep and its checked-in table:

```sh
VIVADO=/path/to/vivado just fpga-sweep-sim --max-n 32 --output docs/fpga-gemm-sweep-n1-32.csv
```

To repeat a hardware point, run `just fpga-bench 16` or `just fpga-bench 111`
with Vivado available. Each command builds and programs all three variants,
checks every output, and prints cycles and execution time.
